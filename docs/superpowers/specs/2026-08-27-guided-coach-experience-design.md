# 引导式人生设计教练体验

## 背景与问题

阶段 1 已经证明八个主步骤、混合题型和断点恢复可以工作，但它仍然像一份被拆开的问卷：页面先抛出抽象概念，再要求用户独立组织答案。用户虽然知道“要回答什么”，却没有感受到有人帮助他回忆、区分和澄清。

这次改造不追求增加问题数量，而是降低每一步的思考门槛，让用户通过连续的小判断逐渐形成自己的答案。

## 路径比较

### 方案 A：完全由 AI 对话推进

优点是追问自然、个性化最强。缺点是开源版本立刻依赖 API Key，费用和模型差异会影响基础流程，断点状态和输出结构也更难稳定验证。

### 方案 B：保留现有表单，只增加提示文案

成本最低，但只能缓解措辞问题。用户面对工作观、人生观和三套五年方案时，仍然会遇到空白页压力。

### 方案 C：规则引导式教练，预留 AI 插槽（采用）

基础流程由确定性的微步骤、选项、例子和本地反思组成，不需要 API 也能完整体验。以后接入 AI 时，只替换“追问建议”和“阶段小结”两个边界，不改变存储、恢复或主要交互。

## 核心体验原则

1. 每屏只处理一个认知动作，例如评分、选重点、回忆一个场景或确认一段小结。
2. 先选择，再表达。任何开放输入前都提供可跳过的选项、句子开头或具体例子。
3. 追问用户刚刚说过的内容，不突然切换到新的抽象概念。
4. 先复述，再解释。系统用“我听到的是……”呈现阶段小结，并允许用户修改；不把规则推断包装成诊断。
5. 明确区分可改变的真问题和暂时无法改变的重力问题，但不逼迫用户接受结论。
6. 不制造额外汇报负担。只收集生成个人蓝图必需的内容，数据默认留在本机。

## 推荐交互结构

页面采用“教练话语 + 单一回应区”的卡片结构，不伪装成即时聊天，也不一次展示整份长表单。

每个微步骤包含：

- 一句承接上文的话；
- 一个当下问题；
- 2–6 个选择卡或语义清晰的评分锚点；
- 必要时出现一个带句首提示的短输入；
- “继续”与“返回”，并持续显示本阶段位置；
- 保存后出现简短回应，再进入下一微步骤。

进度表达从“第 3 步，共 8 步”改为“第一阶段：看清现在 · 3/6”，让用户知道当前任务的意义，而不只是题目数量。

## 第一阶段纵向切片：看清现在

### 1. 安顿下来

教练说明本阶段约需 5–8 分钟，没有标准答案，可以随时停下。用户只需选择“开始看看”或“先了解会问什么”。

### 2. 四个仪表盘

四个维度仍然保留，但每个分数显示语义锚点：

- 0–2：已经明显影响日常；
- 3–5：勉强维持，需要关注；
- 6–8：整体稳定，偶有波动；
- 9–10：很满意，希望保持。

评分后，系统不要求用户解释四遍，而是指出最低的两个维度，让用户选择“这次先谈哪一个”。用户也可主动改选。

### 3. 给困扰一个形状

根据用户选择的维度展示 4–6 个常见困扰卡。例如工作维度可选：

- 总在透支；
- 看不到意义；
- 想换方向但不知道去哪；
- 能力没有发挥；
- 人际或环境让我难受；
- 都不准确，我自己说。

选择后出现一句可编辑的句子：“最近我最困扰的是……”。用户不必从空白文本开始。

### 4. 回到一个真实时刻

不要求一次写完整故事，而是分三次收集：

1. 最近什么时候最明显？可选“今天 / 这周 / 这个月 / 更久以前”，并可补充时间；
2. 当时具体发生了什么？提供与所选困扰匹配的示例；
3. 那一刻最接近什么感受？先选 1–2 个情绪词，再允许补充。

### 5. 区分边界

系统展示三张卡：

- 我能直接尝试改变的；
- 我能影响、但不能完全控制的；
- 目前只能接受或绕开的。

用户把刚才困扰中的因素放入对应区域。系统据此温和提示可能的真问题和重力问题，并提供“说得对 / 不完全对，让我改改”。

### 6. 阶段小结

系统生成一段可编辑的本地模板小结：

> 你现在最想关注的是【维度】。真正刺痛你的不是一个抽象标签，而是【具体事件】带来的【感受】。在这些因素里，【可行动部分】值得进入下一阶段继续设计；【不可控部分】需要作为边界被看见。

用户确认后才进入“你的指南针”。这个确认结果成为后续问题的上下文。

## 后续三阶段的复制方式

### 你的指南针

先从价值卡和两难选择开始，再用句首模板生成工作观与人生观。系统展示两者一致、冲突和需要让步的位置，而不是直接要求用户写两篇抽象短文。

### 寻路

一次只回忆一个具体活动。先从“最近一次有精神 / 明显疲惫 / 忘记时间”进入，再标注能量与投入，三次完成后立即展示简单的能量模式。

### 多种可能

一次搭建一个五年版本。第一个从当前路径延伸，第二个从“如果原路消失”开始，第三个从“暂时不考虑钱和评价”开始。每完成一个先看到一张摘要卡，再开始下一个，避免一屏填写三套庞大方案。

## 状态、数据与 AI 边界

新增确定性的 `GuidanceFlow`：负责当前微步骤、可用选项、承接文案和模板反思。它不负责持久化，也不直接调用模型。

检查点升级为 v3，保存：

- 当前主阶段与微步骤；
- 已确认的结构化回答；
- 尚未完成的草稿；
- 用户修改后的阶段小结。

v2 数据迁移时保留已完成回答，并将用户定位到相关阶段的小结确认处；不要求无意义地全部重答。

未来 AI 通过两个可替换接口接入：

- `suggestFollowUp(context)`：在规则问题之外提供一条可选追问；
- `draftReflection(context)`：生成更自然的阶段小结。

没有 API Key 或调用失败时，规则流程仍可独立完成。API Key 不写入检查点、导出文件或日志。

## 错误与恢复

- 每个微步骤先保存草稿和回答，再推进位置；
- 刷新、关闭页面或浏览器崩溃后回到同一微步骤，并恢复输入内容；
- 保存失败时停留原位，说明内容尚未推进，不清空输入；
- 用户可以返回上一微步骤修改，后续依赖性小结需重新确认；
- AI 不可用时只隐藏可选追问，不阻塞主流程。

## 验收标准

第一阶段纵向切片必须满足：

1. 首次进入不会直接看到空白文本框；
2. 每屏只有一个主要问题和一个主要操作；
3. 任一开放输入都有选择结果、示例或句首模板作为起点；
4. 仪表盘后会基于实际分数让用户选择关注点；
5. 用户至少经历一次“选项 → 具体事件 → 感受 → 边界 → 可编辑小结”的连续引导；
6. 返回和刷新后准确恢复到微步骤及草稿；
7. 规则小结明确标注为复述和假设，不做心理诊断；
8. 412×915 手机视口无横向溢出，不出现三套方案式超长单页；
9. 不配置 API Key 也能完成第一阶段；
10. 自动化测试覆盖选择分支、草稿恢复、返回修改和小结确认。

## 本轮范围与非目标

本轮只实现第一阶段“看清现在”的完整引导纵向切片，并为其余阶段保留现有流程。第一阶段验收后，才按相同结构逐阶段替换。

本轮不接入模型、不做付费、不生成最终人生蓝图，也不重新设计仓库中原有的 Agent/CLI 能力。
